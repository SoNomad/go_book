# Как опубликовать сайт книги и работать с ним

Сайт собирается **из Markdown-файлов в корне репозитория** (главы `00-…18-*.md`, `README.md`, `cheatsheet.md`).
Папка `site/` — это только «оболочка» (VitePress). Правите главы — сайт обновляется сам.

## 1. Опубликовать на GitHub Pages (один раз)

Нужен аккаунт GitHub. Репозиторий **публичный** (так вы выбрали): сайт и код, включая `solutions/`, видны всем.

1. На GitHub: **New repository** → имя, например `go-backend-book` → **Public** → *без* README и `.gitignore` (они уже есть) → Create.
2. В папке книги (корень репозитория) выполните — подставив свой адрес:

   ```bash
   git add .
   git commit -m "Учебник «Go и бэкенд для фронтендера» + сайт"
   git remote add origin https://github.com/<ваш-логин>/go-backend-book.git
   git push -u origin main
   ```

3. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Вкладка **Actions**: workflow «Сайт книги → GitHub Pages» запустится сам после `push`. Первая сборка ≈ 3–5 минут.
5. Адрес сайта: `https://<ваш-логин>.github.io/go-backend-book/` (он же показан в шаге *deploy*).

Дальше каждый `git push` в `main` обновляет сайт. Workflow сначала проверяет примеры на Go (`go vet`, `go test ./solutions/...`) и тесты сайта (синтаксис всех диаграмм и т. д.): **сломанная книга не публикуется**.

> Если репозиторий называется `<логин>.github.io`, сайт будет в корне домена — workflow учитывает это сам.

## 2. Читать на телефоне и офлайн

Откройте адрес сайта в браузере телефона:

- **Android (Chrome):** меню ⋮ → «Установить приложение» / «Добавить на главный экран».
- **iPhone (Safari):** «Поделиться» → «На экран “Домой”».

После первого открытия (по Wi-Fi) главы, поиск и диаграммы работают **без сети**. Обновления подтягиваются автоматически.

**Прогресс** (галочки в «Задачах» и «Самопроверке») хранится **на каждом устройстве отдельно**. Чтобы перенести: страница **«Мой прогресс» → Экспорт** на одном устройстве и **Импорт** на другом — отметки объединяются.

## 3. Локальная работа

```bash
cd site
npm ci            # один раз
npm run dev       # http://localhost:5173 — правки глав видны сразу
npm test          # тесты: синтаксис всех диаграмм, модели визуализаторов, прогресс
npm run build     # production-сборка в site/.vitepress/dist
npm run preview   # посмотреть production-сборку на http://localhost:4173
```

Ссылки на код (`tasks/`, `solutions/`, `labs/`) на сайте ведут в репозиторий на GitHub. Локально они указывают на заглушку `OWNER/REPO` — задайте `REPO_URL` (например, `REPO_URL=https://github.com/логин/go-backend-book npm run build`); в CI это делается автоматически.

## 4. Как добавлять иллюстрации

**Диаграмма** — обычный блок ` ```mermaid ` прямо в главе (его рисуют и GitHub, и сайт). Правила, выученные на практике:

- Не более 4–5 участников в `sequenceDiagram` и короткие подписи — шире ~900 px текст мелеет. Длинные цепочки — вертикально (`flowchart TB`), а не `LR`.
- Подписи с `()` и спецсимволами — в кавычках: `A["Браузер (Angular)"]`.
- Роли цветов едины для всей книги: `:::client` (браузер), `:::service` (наш Go-сервис), `:::data` (БД, Redis), `:::external` (внешнее), `:::ok` / `:::bad` / `:::muted`.
- Проверка синтаксиса — `npm test` (проверяет **все** диаграммы всех глав).

**Интерактивный компонент** — маркер на отдельной строке: `<!-- viz:SliceViz -->`. В обычном Markdown он невидим, на сайте превращается в компонент из `site/.vitepress/theme/components/`. Логику выносите в `theme/lib/*.ts` и покрывайте тестами (значения — из реальных запусков Go/PostgreSQL).

Доступные компоненты: `RequestLifecycle`, `SliceViz`, `RaceViz`, `MiddlewareViz`, `JoinViz`, `IndexViz`, `TxViz`, `TokenBucketViz`, `BreakerViz` (и универсальный `StepPlayer` для новых пошаговых сценариев).

## 5. Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| Страница пустая или `404` на ассеты после пересборки (`preview`) | `vitepress preview` индексирует файлы один раз при старте: перезапустите его |
| Порт 5173/4173 «занят» после остановки сервера | остался дочерний процесс `node`: найдите по `netstat -ano \| findstr :5173` и завершите `taskkill /PID <pid> /F` |
| `EPERM` при сборке на Windows | какой-то терминал стоит в `site/.vitepress/dist` — перейдите в другую папку |
| `BASE="C:/Program Files/Git/..."` | Git Bash превратил `/имя/` в путь Windows — задавайте `BASE=имя` без слэшей |
| Сборка падает на `{{ … }}` или `<тег>` в тексте | Vue читает прозу как шаблон: оберните в обратные кавычки (скрипт `sync-content.mjs` подскажет файл и строку) |
| Сайт открылся, но без стилей на GitHub Pages | не включён **Source: GitHub Actions** (шаг 1.3) либо неверный `base` |
