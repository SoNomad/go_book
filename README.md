# Go и бэкенд для фронтендера (Angular → Go)

Учебник для человека, который уверенно пишет на Angular/TypeScript, но не знает ни Go, ни баз данных, ни Docker, ни того, как вообще живёт сервер в продакшене. Цель — за ~6 месяцев пройти путь от «`go run` hello world» до **задеплоенного сервиса с БД, кэшем, очередями, тестами, CI/CD и мониторингом**, написанного вами самостоятельно.

> Темп: 8–10 часов в неделю. Если у вас 15+ часов — сокращайте сроки пропорционально. Спешить не нужно: бэкенд — это про глубину, а не про скорость прохождения глав.

---

## Как пользоваться

1. **Читайте главу по порядку.** Каждая глава построена одинаково: цели → теория → примеры → задачи → самопроверка.
2. **Все примеры печатайте руками**, не копируйте. Пальцы запоминают синтаксис быстрее глаз.
3. **Задачи — главная часть.** Теория без задач даёт иллюзию понимания. Правило 30/70: 30% времени чтение, 70% — код.
4. **Задачи с пометкой 📦 имеют автотесты** (папка [`tasks/`](tasks/)). Запускаете тесты — они красные — пишете код — они зелёные. Эталонные решения лежат в [`solutions/`](solutions/): заглядывайте только после честной попытки.
5. **Ведите `notes.md`**: что не понял, какие ошибки совершали, какие вопросы остались. Через неделю перечитывайте.
6. **Самопроверка** в конце главы: если не можете ответить своими словами — вернитесь к теории.

Обозначения сложности: 🟢 лёгкая · 🟡 средняя · 🔴 сложная · 📦 есть автотесты.

## Словарь «Angular/TS → Go/бэкенд»

Это главная идея учебника: вы не начинаете с нуля, вы **переводите** то, что знаете.

| Ваш мир (Angular / TS / Node) | Мир Go / бэкенда | Комментарий |
|---|---|---|
| `package.json`, `package-lock.json` | `go.mod`, `go.sum` | Зависимости; нет `node_modules` — кэш в `~/go/pkg/mod` |
| `npm install`, `npm run build` | `go get`, `go build` | Результат сборки — **один бинарник**, без рантайма |
| `ng serve` | `go run .` (+ `air` для hot reload) | Компиляция — доли секунды |
| `tsc` + ESLint + Prettier | `go build` + `go vet` + `gofmt` + `golangci-lint` | `gofmt` — единственный стиль, споров о табах нет |
| Jest / Karma | `go test` | Встроено в язык, не надо ничего настраивать |
| `class` | `struct` + методы | Нет наследования, только композиция |
| `interface` (структурная типизация) | `interface` (тоже структурная!) | В Go реализуется **неявно**; описывает поведение, а не форму данных |
| `@Injectable()` сервис + DI-контейнер | struct + конструктор `NewService(deps)` | DI вручную в `main()`; «магии» нет |
| `HttpClient` | `net/http` клиент | Всегда задавайте таймаут |
| `HttpInterceptor` | middleware `func(http.Handler) http.Handler` | Та же идея «цепочки обработчиков» |
| Route Guard | middleware авторизации | Guard — UX, настоящая проверка только на сервере |
| `ErrorHandler` | `recover` middleware | Паника не должна ронять сервер |
| `Observable` / RxJS | канал (`chan`) + горутина | `switchMap`-отмена ≈ `context.Cancel` |
| `Promise` / `async`/`await` | горутина + канал / `errgroup` | У Go нет «цветных» функций |
| `Promise.all` | `sync.WaitGroup` / `errgroup.Group` | |
| `try / catch` / `throw` | `if err != nil { return err }` | Ошибки — обычные значения |
| `null` / `undefined` | `nil` + **нулевые значения** (zero values) | `int` всегда `0`, `string` — `""`, не `undefined` |
| `enum` / union types | `const` + `iota` | Union-типов нет |
| Generics | Generics (с Go 1.18) | Проще, чем в TS: нет conditional/mapped types |
| Decorators | struct tags `` `json:"name"` `` | Метаданные для `encoding/json`, БД и т. д. |
| `environment.ts` | переменные окружения | 12-factor: конфиг не в коде |
| Один поток + event loop | Много потоков ОС, планировщик горутин | В Go **есть** гонки данных (data races) |
| `ng build` + nginx-образ | multi-stage Dockerfile | Тот же приём, что для Go |
| localStorage / cookies | сессии на сервере, БД, Redis | Состояние живёт на сервере |
| DevTools / Redux DevTools | логи, метрики, трейсы, `pprof` | Наблюдаемость нужно строить самому |

## Как запускать задачи

Из корня этой папки:

```bash
go test ./tasks/ch01/...          # задачи главы 1
go test -race ./tasks/ch05/...    # задачи главы 5 — обязательно с детектором гонок
go test ./tasks/ch02/wordfreq     # одна конкретная задача
```

Тест красный → читайте сообщение → правите код → повторяете. Чтобы сравниться с эталоном: `go test ./solutions/...` (все зелёные).

> 🪟 **Windows и `-race`.** Детектору гонок нужен cgo и компилятор C. Если gcc нет, запускайте тесты главы 5 в Linux-контейнере (подробности и команды — в [главе 5](05-konkurentnost.md#52-гонки-данных-и-sync)):
> ```powershell
> docker run --rm -v "${PWD}:/src" -w /src golang:1.24 go test -race ./tasks/ch05/...
> ```

## Принципы, на которых стоит учебник

- **Простота важнее хитрости.** Go намеренно скучный язык. Если код выглядит «умно» — скорее всего, он плохой.
- **Явное лучше неявного.** Ошибки возвращаются, зависимости передаются, конфиг читается — всё на виду.
- **Стандартной библиотеки хватает дольше, чем кажется.** Мы начнём с `net/http` и `database/sql`-стиля и добавим сторонние пакеты только когда они реально нужны.
- **Бэкенд — это про последствия.** Потерянные данные, дыры в безопасности и упавший сервис дороже любой красивой архитектуры. Поэтому тесты, транзакции и наблюдаемость — не «факультатив».

## Как проверялся материал

Чтобы учебник не учил неработающему, примеры проверялись, а не только писались:

- **Go-код.** Все полные программы из текста (25 штук, включая примеры на `pgx`, `go-redis`, `bcrypt`, JWT, Prometheus) компилируются и проходят `go vet`; ключевые из них запускались, а заявленный вывод сверен с реальным (ловушки слайсов и `nil`-интерфейса, сессии и cookie через `curl`, маршрутизация и `405`, `/metrics`, SSE-стрим, token bucket и circuit breaker).
- **Задачи.** Для всех 18 📦-задач эталонные решения проходят тесты, а заглушки — **падают** (иначе тест ничего бы не проверял).
- **SQL.** Схема, данные и все решения главы 7, а также запросы транзакций и очереди из глав 8 и 13 выполнены на настоящем движке PostgreSQL (WASM-сборка); результаты и цифры в тексте — оттуда.
- **Тесты на `miniredis`, `testcontainers`-сниппет, OpenAPI → TypeScript** — выполнены/скомпилированы против реальных библиотек и генератора.
- **Не выполнялось на стороне автора** (нет демона Docker и сервера): сборка образов, `docker compose up`, GitHub Actions, Kubernetes, Caddy/systemd, gRPC-генерация кода и `oapi-codegen`; тест гонок `-race` (нет C-компилятора под Windows). Конфиги Compose и YAML проверены синтаксисом (`docker compose config`, YAML-парсер). Версии образов, действий CI и плагинов со временем меняются — сверяйтесь с документацией.
